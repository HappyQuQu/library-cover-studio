# 中文优先的 i18n 支持可行性方案

日期：2026-10-14。基线：`a428823`。需求分支：`codex/feat-i18n-plan`。

**可行，建议沿用现有 i18next 和 react-i18next，第一版完成简体中文与英文界面。** 中文作为默认语言与缺失翻译的回退语言，用户可在登录页和应用内随时切换。主要工作是补齐文案、统一错误展示和验证英文布局；前端语言选择不需要新增数据库字段、改变部署方式或重建模板。

本文记录实施方案与五个阶段的交付。首版覆盖产品自有界面和常见操作反馈；用户创建的内容、社区模板说明、历史日志和发布正文保留原文。

## 第一阶段交付

第一阶段已实现中文默认、en 及英文地区变体归一化、独立语言偏好存储、同源标签页同步与页面 lang 和描述更新。登录与注册界面、设置中的外观页提供语言入口；普通用户与管理员均可使用。浏览器存储受限时，当前页面继续使用已选择的语言。

词典已按语言和模块拆分，现有缺失 key 已补齐，两种语言各 111 个条目。英文通过递归类型约束与中文保持相同结构，t 调用接入类型检查；已有设计器调用中的中文默认值已移入词典。pnpm check:i18n 已接入 CI，检查空翻译、key 一致性、插值参数、复数结构和已接入模块的翻译调用。全站固定中文扫描与其余页面迁移继续按后续阶段推进。

语言偏好、存储受限、并发切换、失败恢复、跨标签页事件、文档属性和检查器错误路径共有 8 项回归测试。Node 22 下全量 28 个测试文件、122 项测试及前后端构建通过；浏览器验证了中英文切换、刷新、登录退出后的保留、普通用户设置入口，以及切换时未保存画布、模板名和撤销状态的保留。设置和设计器验证使用隔离模拟接口。

新增或修改界面文案时，需同时更新两份模块词典，使用完整句子与命名插值，并运行 pnpm check:i18n 和 pnpm build。第一阶段仅交付语言基础设施及上述入口；导航、其他业务页面和完整错误反馈的迁移仍属于后续阶段。

## 第二阶段交付

导航、账号菜单、设置侧栏、仪表盘、媒体源、模板库，以及关于和版本记录界面已接入中英文词典。通用弹窗关闭按钮、通知区域和关闭通知按钮同步翻译。中文仍是首次访问的默认语言；服务器名、媒体库名、模板名称与说明、发布正文保留原文。

媒体源与模板库的加载、空状态、失败与重试入口、确认提示和操作通知已迁移。模板导入保存错误类型与原始错误对象，切换语言时重新生成提示，保留当前文件名。现有业务错误码通过统一工具翻译，原始诊断使用可折叠的「诊断详情（原文）」展示；未扩展后续阶段的全站后端错误协议。登录接口的 401 不再触发令牌刷新和页面重载，凭据错误能留在登录页显示。

仪表盘数字、媒体库单复数计数、最近运行时间和发布相关日期跟随界面语言显示，不修改原始时间戳或调度配置。为英文长文案调整了按钮换行与仪表盘窄屏布局。

两种语言各 304 个词条，新增 4 项回归测试覆盖单复数、用户内容保留、日期和时区、错误码、诊断与固定中文扫描。已完成的 13 个页面及公共组件纳入 pnpm check:i18n 扫描，防止界面新增固定中文。Node 22 下全量 29 个测试文件、126 项测试及前后端构建通过。

隔离浏览器验证覆盖中英文服务器表单切换和输入保留、添加成功与连接失败、模板复制、文件格式错误、ZIP 校验失败、成功导入与导出、登录失败与注册界面文案、普通用户与管理员导航，以及发布正文保留原文。英文仪表盘检查了 390、1024、1440 像素宽度，模板库检查了 390 像素宽度，页面无整体横向溢出；导航保留横向滚动以访问全部入口。浏览器中的媒体 API 与导入导出使用隔离模拟接口，实际后端继续由回归测试验证。

## 第三阶段交付

设计器（工具箱、图层、属性、背景、模板信息、保存历史与草稿提示）、模板商店、任务列表与四步向导、执行计划和执行历史已接入双语词典，首次访问及缺失翻译仍优先使用中文。新增账号菜单快捷入口，并在任务向导和模板信息弹窗内提供原地切换语言，避免为切换而离开未保存的工作。

界面选项在渲染时翻译，任务排序、星期、频率、图层与步骤使用稳定标识。向导校验和接口失败状态保存提示代码或原始错误对象；切换后重新生成显示文本，不清空步骤、标题、模板、媒体库勾选和展开状态。画布初始化、模板加载、背景同步和样张请求不依赖语言；现有暗角和噪点的持久化名称保持兼容。未命名图层使用可翻译的显示名，进入重命名后没有实际修改则不写回画布。

样张接口增补 noteCode 和 noteParams，保留旧 note、posterCount 和 image；前端可即时翻译已缓存样张的说明，旧接口或未知说明码显示通用本地化提示，原始说明可在诊断详情中查看。执行计划校验失败增补 INVALID_SCHEDULE，保留原字符串 error 和 timezone。阶段内的商店、样张、任务与历史错误码已映射，旧历史诊断保持原文。日期、计数和耗时跟随界面语言显示；Cron、调度时区与时间戳不随语言变化。简易计划解析拒绝越界时间，避免无效 Cron 被描述为正常计划。

英文长文案补充了任务卡片窄屏换行、商店弹窗边距和通用弹窗层级，防止导航遮挡弹窗。已完成的 25 个页面、组件及 Hook 纳入固定中文扫描；检查器通过 TypeScript 字面量联合类型逐项验证动态 key 映射，过宽字符串仍不允许。两种语言各 870 个词条。

Node 22 下 pnpm check:i18n、全量 31 个测试文件共 132 项测试、前后端构建均通过。新增 6 项回归测试涵盖语言切换后的任务与计划数据、校验和缓存样张、旧接口兼容、历史诊断与耗时边界、错误码和动态 key 映射；实际预览控制器使用临时数据库与本地媒体服务验证三类样张说明、旧字段兼容、原设计不变，以及预览不写任务历史、不上传媒体封面。构建仍存在主包超过 500 kB 的非阻断提示，代码拆分留待独立优化。

浏览器验收使用隔离模拟 API：中英文切换后，未保存模板名、画布文字、模板信息、撤销/重做、背景来源、任务标题、排序、勾选、展开项、自定义 Cron 与样张保持可用；比对保存请求确认原始字段未被翻译，重复切换未增加样张请求。覆盖商店搜索、排序、分页、更新确认、备份更新和 AI 制作帮助/提示词复制，任务启动、样张失败与重试、历史展开、大图切换和原图下载。检查 390、1024、1440 像素宽度下的主要工作区，页面无整体横向溢出，导航与设计器工具栏保留各自的横向滚动。实际媒体执行、商店安装与历史图片由后端回归测试验证；浏览器没有访问或修改真实媒体服务器。

## 第四阶段交付

全部设置页已接入双语词典，包括渲染、存储与历史保留、字体、数据维护、默认模板恢复、用户与密码表单、网络设置、AI 服务与系统提示词编辑，以及日志控制和连接状态。中文仍为默认与回退语言。AI 服务预设、模型能力说明、加载与校验、连接测试、保存与失败通知均使用当前界面语言；服务配置名称、模型标识、自定义 URL 和系统提示词继续保留原值。

AI 助手的范围选择、参考图、快捷指令、进度、停止、错误、结果比较、继续调整与预览反馈已迁移。界面反馈保存语义描述，在渲染时翻译；用户消息、参考图分析、模型输出、画布 JSON、系统指令与发给模型的请求不依赖界面语言。快捷指令和继续调整提示仅在用户主动点击时填入输入框，之后按草稿保留。预览渲染、请求控制器、比较状态和对话 ID 不因语言切换重建；停止、失败或流提前结束后保留需求和参考图。

AI HTTP 与 SSE 错误、OpenAI 格式修正进度、模型目录警告、参考图校验和字体错误增补稳定 code，网络检测结果增补稳定目标 id。旧 error、content、warning、label 与 message 字段保持兼容；已知反馈按 code 翻译，未知或旧接口反馈显示本地化通用提示，原始诊断可展开查看。日志正文保持原文，日志时间仅格式化显示；连接生命周期独立于语言，断开时保留已有条目并支持手动重连。

设置初始化不依赖语言，网络查询更新不会覆盖已有修改，系统提示词折叠再展开不会覆盖空白草稿。渲染与保留设置保存失败后保留输入；移焦到语言或账号入口时不提交尚未完成的自动保存字段。AI 服务编辑与用户表单提供原地语言入口。AI 面板标题栏容纳语言选择，英文长文案及设置卡片支持换行，窄屏工作区可滚动访问全部操作。

两种语言各 1,241 个词条，35 个已迁移页面、组件与工具纳入固定中文扫描。Node 22 下 pnpm check:i18n、33 个测试文件共 139 项测试及前后端构建通过。新增 7 项测试涵盖模型指令和内容边界、语义反馈、单复数、旧错误兼容、流中切换与异常帧、参考图校验，以及本地网关下三种 AI 适配器的错误码和原始字段兼容；已有生成重试测试补充进度与错误码断言。构建保留主包超过 500 kB 的非阻断提示。

隔离浏览器验收覆盖 AI 配置和系统提示词草稿、网络模式与 URL、用户表单、渲染保存失败、日志筛选与重连；切换语言没有提交未保存质量值，也没有额外重建日志连接。AI 验证包括参考图上传、流中中英切换、结果比较、应用画布、继续调整、停止、限流、旧格式错误及异常 SSE；原需求、分析原文、参考图、预览与继续调整输入保持不变，流中切换只发送一次生成请求。设置与 AI 工作区检查 390、1024、1440 像素宽度，无页面整体横向溢出，窄屏通过工作区与局部滚动访问控件。浏览器使用本地模拟接口与测试数据，没有调用真实 AI 服务、改动真实网络配置或用户凭据。

## 第五阶段交付

已完成全站文案校对与双语回归。英文按钮、表单和标题采用一致的句式大小写，修正媒体库选择计数的单复数、每日计划预设和 AI 模型能力覆盖说明；中文统一提示词相关用语。补齐通知区域、设计器坐标/尺寸/颜色/字体/透明度/圆角/阴影等属性的可访问名称，并将海报绑定预览的替代文本接入翻译。界面语言继续保持中文默认与中文回退，不新增语言检测、数据库字段或模型语言指令。

固定中文检查扩展到整个 web/src 的 74 个 TS/TSX 文件，新页面和工具无需登记即可受检。源内容仅按文件与精确原值豁免，并记录原因：语言自称、现有画布效果标识和 AI 模型指令。新增英文词典残留中文和调用处 defaultValue 检查，避免默认文案掩盖缺失翻译；实际英文硬编码和文案含义仍由人工复核。两种语言各 1,246 个词条，自动测试逐条渲染，验证无裸 key 或未替换插值。

新增 [中文贡献规则](../CONTRIBUTING.md)、[英文贡献规则](../CONTRIBUTING.en.md) 和 [双语验收清单](I18n_QA.md)，明确完整句子、复数、日期时区、异步反馈、语义错误、源内容与状态保护、精确例外和必跑检查。两份 README 增补界面语言能力、入口、持久化、回退与内容边界，加入英文向导示例及贡献/验收链接；模板变量示例更正为渲染器实际使用的 primary_title 和 secondary_title。

新增可重用的本地浏览器模拟接口 tests/fixtures/i18n-server.cjs（pnpm dev:i18n-fixture）。它只监听回环地址，使用内存数据和内置图片，不调用真实媒体服务、GitHub 或 AI，也不写真实数据库；请求记录隐藏凭据和参考图正文。独立测试保证计划预览和保存后的执行时刻一致，并验证旧反馈字段、原始输入与诊断兼容。

浏览器完成中文与英文的登录、媒体源检测、任务样张/计划/保存/启动/执行历史与原图下载，并分别回归中文模板复制、英文商店下载、设计器属性和保存。向导各步骤、全部主要页面和设置分区、图层面板检查 390、1024、1440 像素宽度，页面没有整体横向溢出；手机向导底部操作可见，导航、工具栏与长面板使用局部滚动。跨标签页切换保留未保存设计名称、选中属性、绑定、撤销/重做；保存请求确认文字和绑定不变，Cron 与调度时区未被改写。AI 流中切换仅发送一次生成请求，原需求和模型分析保持不变。独立源验证语言偏好隔离，同源标签页验证同步；不同浏览器配置文件可按验收清单在发布环境抽查。

Node 22 下 pnpm check:i18n、35 个测试文件共 145 项测试、前后端构建及 git diff --check 通过。前四阶段的导入导出、商店更新/备份、模板历史、设置草稿、参考图和 SSE 错误等自动回归全部重跑。实际渲染、媒体适配器、历史、调度与 AI 协议由临时数据库和本地服务集成测试验证；浏览器结果来自隔离模拟响应，不视为真实媒体上传、外部下载或付费 AI 验证。主包约 617 kB 的非阻断构建提示保留为独立代码拆分优化。

提交前复审补齐异步通知使用当前语言的检查，修复通知与弹窗层级、字体上传大小限制上下文；在隔离浏览器中用延迟请求验证了中途切换后的通知与输入保留。

五阶段范围已交付，后续新增界面遵循贡献规则与全站检查；源内容翻译、旧历史重写和额外语言仍属于独立需求。

## 实施前的基础与缺口

| 项目 | 当前情况 | 对实施的影响 |
| --- | --- | --- |
| 依赖 | 本地安装版本为 i18next 23.16.8、react-i18next 14.1.3、语言检测器 7.2.2 | 可以复用现有版本，先不同时进行依赖大版本升级 |
| 初始化 | [i18n.ts](../web/src/lib/i18n.ts) 已在 [main.tsx](../web/src/main.tsx) 中加载 | 已有统一入口，但未明确限制支持语言、检测顺序和存储策略 |
| 词典 | 实施前的[中文](../web/src/locales/zh-CN/index.ts)和[英文](../web/src/locales/en-US/index.ts)各 61 个叶子 key，结构相同 | 现有词典只是起点，需要扩充到全部页面和反馈 |
| 接入范围 | 35 个 TSX 文件中，只有 EditorPage、LayerPanel、PropertyPanel、Toolbar 使用 useTranslation | 登录、导航、媒体源、模板商店、任务和设置等仍需接入 |
| 已有缺失 | 静态字符串形式的 t 调用涉及 29 个不同 key，其中 11 个在两份词典中均不存在 | 当前依赖调用处的中文默认文案，英文界面也会出现中文 |
| 文案规模 | 33 个 TS 或 TSX 文件中扫描到 1242 个包含汉字的文本或字符串语法节点 | 工作量集中在任务向导、设置、商店和 AI 面板 |
| 格式化 | 多处日期写死 zh-CN，部分使用浏览器默认语言 | 需要统一日期、数字、持续时间和时区展示 |
| 后端反馈 | 中间件已有 error.code，但控制器还存在字符串 error、原始异常与中文预览说明 | 前端界面翻译之外，还需兼容旧接口并补充语义码 |

文案扫描包含默认值、提示词、示例及业务数据，不包含注释。1242 是待审查的语法节点数，**不等于需要翻译的条目数**；后续需按语义去重和区分界面与内容。

缺失 key 为：

```text
common.width
common.height
common.select
designer.noLayers
designer.noSelection
designer.selectionHint
designer.rotation
designer.fontFamily
designer.background
designer.addElement
designer.sampleText
```

基于当前资源与 fallback 配置进行的独立运行检查显示：en-US 的 common.save 为 Save，但 designer.noSelection 使用调用处中文默认值；显式选择 en 或 en-GB 时，common.save 回退为「保存」。这说明需要单独处理语言归一化，不能仅依赖中文 fallback。

| 日期和数字 | 使用当前界面语言格式化，明确区分显示语言与执行时区 |
| 用户内容 | 服务器名、媒体库名、模板名、主副标题、画布文字、作者说明和 AI 会话保留原文 |
| 内置模板 | 首版保留已有名称与设计内容；复制后的内容由用户编辑 |
| 社区与发布内容 | 页面控件翻译，社区元数据和 Release 正文按源语言展示，必要时注明「原文」 |
| 日志与旧执行历史 | 状态与操作控件翻译，历史 errorMessage、控制台日志和第三方诊断保留原文 |
| AI 生成 | 翻译助手界面；生成内容的语言由用户需求或提示词决定 |
| 后续语言 | 首版只交付 zh-CN 和 en-US，扩展语言使用同一资源结构 |

## 语言选择与持久化

### 中文默认与显式选择

推荐首版提供「简体中文」「English」两个选项：登录页可直接切换，应用内在「设置 → 外观 → 语言」切换，普通用户与管理员均可使用。语言是浏览器偏好，不作为管理员的全局系统配置。

解析顺序为：有效的显式语言偏好 → 简体中文。首次访问始终使用中文，不根据浏览器语言自动改成英文。这样延续项目中文优先的入口，也避免初始化检测器、浏览器语言和页面 lang 之间互相覆盖。

语言归一化规则：

- zh、zh-CN、zh-Hans 统一为 zh-CN；zh-TW、zh-HK 等中文变体首版使用简体中文回退，不声称提供繁体翻译。
- en 和 en 的地区变体统一为 en-US。
- 不支持或无效的值回退为 zh-CN。

使用独立 localStorage 项 `lcs-language` 保存显式选择，登录、退出和刷新后继续生效。现有 `i18nextLng` 可能是检测器自动写入的结果，不能认定为用户主动选择；首版不自动迁移它，也不删除它。存储不可用时，在当前页面内维持选择，刷新后使用中文。

可继续保留语言检测器依赖，但初始化由应用显式解析 lng，关闭其自动缓存，避免两套存储共同决定结果。浏览器跟随模式如后续需要，应新增明确选项，而不是悄悄改变默认规则。检测器可配置检测来源和缓存，[官方说明](https://github.com/i18next/i18next-browser-languageDetector#detector-options)支持这种受控使用方式。

### 切换行为

通过单一语言入口调用 i18n.changeLanguage，并同步 `document.documentElement.lang`、页面描述和格式化语言。React 组件通过 useTranslation 更新。[官方 Hook 文档](https://react.i18next.com/latest/usetranslation-hook)提供语言切换接口。

语言切换只更新展示，保持当前路由、表单输入、任务向导步骤、画布对象、未保存草稿、撤销历史和登录状态。不要给页面或 Fabric 画布设置随语言变化的 React key，避免重新挂载。

监听 storage 事件同步同源标签页；同页由语言入口直接更新，避免依赖不会在本页触发的 storage 事件。切换失败时保留当前有效语言与选择状态。

## 词典与前端组织

### 保留现有调用习惯

首版保持默认 translation namespace 和字符串 key 的调用方式，避免同时迁移现有 t 调用。将词典按语言和业务模块拆成 TS 文件，在资源入口组合：

```text
web/src/locales/
  zh-CN/
    common.ts
    navigation.ts
    auth.ts
    dashboard.ts
    servers.ts
    templates.ts
    templateStore.ts
    designer.ts
    tasks.ts
    settings.ts
    ai.ts
    releases.ts
    errors.ts
    index.ts
  en-US/
    ...相同模块
```

两种语言先随应用打包，无需远程翻译服务或新的运行时请求。模块拆分用于维护；namespace 按需加载留到实际包体积有需要时再做。

中文资源作为 key 和嵌套结构基准，英文使用递归映射类型约束相同结构，叶子值放宽为 string；不要让英文值被约束成中文字符串字面量。通过 i18next 的 CustomTypeOptions 为 t 提供类型检查，继续使用当前 v23 支持的方式，不引入新版本 selector API。[v23 类型定义](https://raw.githubusercontent.com/i18next/i18next/v23.16.8/typescript/options.d.ts)提供资源类型扩展入口。

### 完整句子与语义 key

采用 `tasks.schedule.weekly`、`templateStore.download.pending` 等语义 key，完整句子使用命名插值。英文可调整词序，避免将中文词片段拼接成句。

```tsx
// 建议用法，待实施
t('tasks.schedule.weekly', { weekday, time });
t('templates.deleteConfirm', { name: template.name });
t('templateStore.results', { count: total, start, end });
```

英语计数资源使用 _one 和 _other，中文资源也保持相应结构以便统一检查。复数形式由 count 决定，不能给英文统一追加固定单词。[复数文档](https://www.i18next.com/translation-function/plurals)说明了这一约定。

缺失英文可在运行时回退中文，但 CI 必须拦截发布范围内的缺失 key 和插值不一致。移除用中文 defaultValue 隐藏缺失词典的习惯；保留必要的内容默认值，但将它与界面词典明确区分。

### 避免冻结已翻译文本

[taskConfig.ts](../web/src/lib/taskConfig.ts) 的排序项、星期和计划描述，以及任务向导的步骤，改为值与 key 的映射，在组件渲染时翻译。语言相关 useMemo 必须依赖 t 或当前语言。不要在模块加载时调用 t 并长期保存结果。

状态中优先保存语义状态、错误 code 和插值参数，渲染时生成文案。已有 Toast 可在产生时使用当前语言，不要求追溯翻译旧通知。

## 日期格式与任务时区

增加统一格式化工具，为 Intl.DateTimeFormat 和 Intl.NumberFormat 显式传入当前语言。日期、整数、下载量、文件大小与持续时间使用一致的处理方式。

任务时间必须继续使用服务器返回的 scheduler timezone。例如每周一 04:00、Asia/Shanghai，切到英文后只改变文字与日期格式，不改变 Cron、时区、下次执行时刻或已保存任务配置。任务计划与历史页显示相关时区，避免用户将显示格式误认为执行时区。

[后台时间工具](../backend/src/utils/time.ts) 当前生成带时区偏移的时间字符串；首版保留存储格式，格式化时按时间戳解析，禁止依靠切割字符串或补 Z 改变时间含义。普通日志和版本时间可使用浏览器时区，并在需要时说明。空日期和无效日期都需有本地化回退。

## API 错误与后端兼容

### 复用现有错误码

[errorHandler.ts](../backend/src/middleware/errorHandler.ts) 已支持 error.message 与 error.code。沿用这一结构，按业务补充稳定 code 和可选 params：

```json
{
  "error": {
    "code": "MEDIA_LIBRARY_NO_POSTERS",
    "message": "媒体库没有可用海报，无法生成封面",
    "params": {}
  }
}
```

message 保留兼容和诊断用途，前端优先用 code 翻译。已知业务错误先补齐登录、权限、媒体服务器连接、模板导入、样张、执行、AI 服务和网络配置。现有 VALIDATION_ERROR 等粗粒度代码逐步增加字段与规则信息，只传字段名、约束值等结构化参数，不把整个异常对象或凭据作为 params。

建立统一 getLocalizedError，兼容当前字符串 error、嵌套 error.message 和 Axios 网络异常。未知 code 不直接显示词典 key；显示当前语言的通用提示，诊断详情保留原始消息。HTTP 状态只能作为兜底，不能从 400 推断具体业务原因。

语言显示由前端决定，首版不按 Accept-Language 修改服务端全局行为或缓存；同一服务器可以同时被不同语言的浏览器使用。

### 动态说明和持久化历史

[任务样张接口](../backend/src/controllers/taskPreview.controller.ts) 的 note 目前为中文。增加 noteCode、noteParams，并保留 note，前端按 code 渲染；AI SSE 的错误事件同样增加稳定 code，兼容旧 error 字段。

任务执行与单库历史目前保存 errorMessage。首版翻译状态和当前业务错误，旧历史详情保留原文；不通过中文字符串匹配重写历史。若后续要求任意语言回看历史详情，再为记录添加可空 errorCode 与 errorParams 字段，旧记录仍保留原始消息。

## 模板与 AI 内容边界

**切换界面语言不得自动更新模板、任务标题或画布文字。** 现有中文模板、字体包、共享模板引用和已保存任务应继续正常渲染。将内置模板中文名称直接替换成英文数据库值会影响用户辨识和历史，因此首版保持内容原样。

新建文字元素可以按当前语言使用一次性的示例文案；创建后它就是用户内容，之后切换语言不再改写。空状态和按钮即时翻译，示例画布内容与这些界面文案使用不同的生命周期。

AI 助手的提示、按钮、能力说明和失败状态翻译；系统提示词、用户自定义提示词、对话历史与模型返回结果不因界面语言切换而重写。需要英文生成内容时，由用户提示或后续独立的生成语言选项决定。

## 验证与验收

### 自动检查

在现有 pnpm test 和 pnpm build 基础上，新增 pnpm check:i18n 并接入 CI：

1. 比较两份词典的完整 key、插值参数与复数形式，英文叶子不能为空。
2. 扫描 TS 与 TSX 的界面文字、属性、默认值、Toast 和确认框，区分注释与用户内容；维护带理由的例外清单。
3. 静态 key 由类型与扫描校验，动态状态 key 通过显式映射和枚举测试验证，避免过宽的动态字符串。
4. 覆盖语言归一化、localStorage 失败、多标签页、日期无效值、count 为 0 或 1、已知与未知错误，以及旧 API 格式。
5. 复用现有 node:test 与 tsx 验证纯函数和词典；为实际浏览器流程选择可复用的浏览器测试方式，避免只验证源码包含 t 调用。

### 浏览器验收

| 场景 | 验收标准 |
| --- | --- |
| 中文默认 | 干净浏览器无偏好时显示中文，即使 navigator.language 为 en-US |
| 选择与持久化 | 登录前后均可切换；刷新、退出和重新进入保留显式选择 |
| 内容保护 | 打开未保存设计或任务向导切换语言后，画布、撤销历史、输入和选中项保持一致 |
| 多语言访问 | 两个独立浏览器可分别使用中文与英文；同源标签页同步语言偏好 |
| 主要流程 | 两种语言均完成登录、媒体源连接、模板复制和商店下载、真实样张、任务保存、执行与历史下载 |
| 日期与调度 | 同一任务在两种语言下的 Cron、timezone 和时间戳完全相同，格式变化正确 |
| 失败反馈 | 凭据错误、权限不足、无海报、模板包无效、网络失败和 SSE 错误均有本地化提示 |
| 英文布局 | 在 1440、1024、390 像素宽度检查导航、设置、四步向导与图层面板，无文本截断或操作不可达 |
| 辅助文本 | 页面 lang、关闭按钮、图标按钮、图片替代文字与确认框跟随语言 |
| 回退与原文 | 无裸 key；用户内容、社区说明、发布正文与旧历史诊断保留原文并可辨识 |

## 风险与控制

| 风险 | 控制方式 |
| --- | --- |
| 中英文混杂 | 完整词典和调用检查、业务错误码、英文流程验收，分别处理界面文案与源内容 |
| 英文文本更长 | 调整换行、按钮最小宽度和导航收缩，不依靠缩小全局字号解决 |
| 切换语言丢草稿 | 不重新挂载页面或画布，测试带未保存内容的实时切换 |
| 误改封面内容 | 界面资源和模板数据分离，不在语言切换时写数据库或替换画布文本 |
| 时区被语言覆盖 | locale 只控制显示，scheduler timezone 独立，测试时间戳与 Cron 不变 |
| 接口兼容性 | 新增 code 或 params，保留旧 message 与 note，不改变 HTTP 状态和任务业务参数 |
| 文案持续回退 | 将新文案的双语词典与 CI 检查纳入贡献要求，fallback 仅作运行时保护 |

五阶段已按用户工作流交付，后续维护遵循贡献规则与验收清单。首版不需要数据库语言字段；持久化历史错误的语义码和内置模板显示别名可作为后续独立需求。
